# 0.2.2 - close the anonymous first-admin window, bound unauthenticated bodies

Status: implemented, tests green (129). Not released; no version bump, no
manifest or catalog change. Ship as 0.2.2 per `AGENTS.md` section 5.

Both changes are in `src/proxy.ts` plus `src/config.ts`; the rest is docs and
tests. Nothing here touches the image, the dependency pins or the release gate.

## 1. The first-admin bootstrap required no credential at all

`POST /npubs` was unauthenticated for as long as `routstr_auth_npubs` was empty,
and the first caller became `admin`. The README said so plainly, but the
deployment makes it worse than that wording suggests:

- `httpPort: 8008` is proxied by Cloudron and `handle()` sends
  `Access-Control-Allow-Origin: *`, so the window is reachable from any
  browser on the internet, cross-origin included.
- The app has no Cloudron auth wall, so nothing sits in front of it.
- `POSTINSTALL.md` did not tell the operator to register immediately, and the
  window does not expire. An install left unconfigured overnight was claimable
  by a scanner.

Admin is not a small grant: `POST /wallet/send/bolt11`, `GET /keys/api`
(every provider credential in plaintext), `POST /wallet/check-proofs`,
`DELETE /npubs/<owner>`.

### Fix

A one-time bootstrap token, minted at startup only while the npub table is
empty (or taken from `ROUTSTRD_AUTH_BOOTSTRAP_TOKEN`) and printed to the app
log. `POST /npubs` requires it in `x-routstr-bootstrap-token` while the table is
empty; the first successful claim nulls it. Comparison is constant-time.

Rejected alternatives:

- **Loopback-only bootstrap.** Fails on both deployment paths: Cloudron's nginx
  reaches the app from the host/bridge address, and `docker run -p 18008:8008`
  makes a host-loopback caller appear as the bridge gateway. Unverifiable from
  inside the container, so it would be a control that only looks like one.
- **Require a valid NIP-98 signature instead.** Any keypair can sign; no barrier.
- **Refuse to start until an admin is configured.** Turns a bootstrap problem
  into a container crash-loop, and Cloudron shows a red app with no path forward.

Cost: `routstrd npubs register` does not send the header, so the *first* admin
is claimed with the `curl` in `POSTINSTALL.md` / `README.md`. Every later
add/update/list goes through the CLI as before. A CLI `--bootstrap-token` flag
would remove the one manual step; that belongs in the CLI repo.

Deleting every npub re-empties the table, and the proxy does not mint a token
in that state (it only mints while there is a window to protect at startup), so
the endpoint answers 403 until a restart supplies one. That is deliberate: an
operator who removes the last admin has locked themselves out, and the recovery
is a restart, not a public endpoint. Worth revisiting if the last-admin guard
(finding 8 in #1) lands.

## 2. Management bodies were buffered before authentication

`handleClients` and the `POST`/`PATCH`/`DELETE` `/npubs` handlers called
`req.arrayBuffer()` before any credential was checked, so an anonymous caller
could make the proxy buffer an arbitrary body and receive the 401 afterwards.
The container is capped at 512 MB (`memoryLimit`), and `server.timeout(req, 0)`
lifted the idle timeout for every request, so a slow body could be parked too.

### Fix

- Credentials are decided from headers first: `requestAuthorization()` for
  everything, or the bootstrap token for the anonymous `/npubs` claim. Nothing
  is read from the body until that passes.
- `readBody()` checks the declared `Content-Length` and then reads the stream in
  chunks, abandoning the request at 1 MiB and answering `413`
  (`code: request_body_too_large`). A chunked body with no length is bounded by
  the same counter.
- `server.timeout(req, 0)` moved from the fetch callback to the two
  authenticated branches, so streaming inference keeps its long quiet periods
  and anonymous requests keep Bun's default idle timeout.

Not changed: the NIP-98 inference path still buffers (it must, to hash the
payload) and still has no cap. That path requires a registered npub, so it is a
post-authentication memory concern rather than an anonymous one. A follow-up
should give it the same bounded reader at a much larger limit (image edits can
carry base64 payloads).

Bun pulls a `ReadableStream` request body eagerly on its own, so a test cannot
assert "the body was never pulled". The ordering test asserts 401 (not 413) for
an anonymous request that declares an oversized body, which is the observable
consequence of checking headers first.

## Tests

129 pass (`bun test`), up from 119. New coverage: claim refused without the
token and with a wrong one; a valid NIP-98 event does not substitute for the
token; the token is accepted, then voided; an operator-supplied token works and
is not regenerated; no token is minted when an npub exists; anonymous oversized
body gets 401, authorised oversized body gets 413 by declared length and by
stream, and a body just under the limit still parses.

## Box test before release

1. Fresh install: the log prints a token; `curl` with it returns 201 and the
   next claim returns 401.
2. `ROUTSTRD_AUTH_BOOTSTRAP_TOKEN` set in Cloudron: no token in the log, the
   configured value is accepted.
3. Streaming chat still survives a >10s quiet period (the timeout move).
4. `routstrd npubs list` / `add` with an existing admin still work.
